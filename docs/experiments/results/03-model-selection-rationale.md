# 模型选择：为什么选用 Random Forest？

## 文档目的

本文档记录 Rep Segmentation 任务的模型选择过程，包括所有候选模型的评估、对比和最终选择 rationale。论文中的 Method / Model Selection 部分应直接引用此文件。

## 二、模型选择理由

### 2.1 六大优势

**1. 因果性保证实时部署**
- trailing window 设计确保每个预测只依赖过去数据
- 满足在线实时要求（延迟 1.15s，对 2-4s 的 rep 周期完全可接受）

**2. 轻量适合嵌入式**
- 模型大小 ~200 KB
- 8 个 per-action 模型共 ~1.6 MB
- 64MB RAM（LuckFox Pico Zero）轻松容纳

**3. 纯 CPU 推理**
- 无需 GPU/NPU
- ARM Cortex-A7 单核即可实时运行
- 推理复杂度：O(n_trees × depth) ≈ 1000 次比较/样本

**4. 结果完全可复现**
- 固定 random seed 后，相同配置产生完全相同结果
- vs 深度学习的不稳定性（TCN 同一架构不同运行：F1 从 0.78→0.68→0.53）

**5. 可解释性强**
- 可分析每个特征对 rep boundary 决策的贡献
- 特征重要性分析可直接指导特征工程改进
- 决策路径清晰，便于调试和论文论证

**6. 精度-延迟-可部署性三角的最佳平衡**

| 维度 | Causal RF | BiLSTM | TCN | Peak Detection |
|------|-----------|--------|-----|----------------|
| Rep F1 | 0.778 | ~0.80 | 0.69 | 0.757 |
| 因果 | ✅ | ❌ | ✅ | ✅ |
| 可部署 | ✅ | ❌ | ⚠️ | ✅ |
| 模型大小 | ~200 KB | >1 MB | ~500 KB | 0 KB |
| 稳定性 | 高 | 中 | 低 | N/A |

### 2.2 为什么没有选深度学习？

**不是因为深度学习不好，而是因为「对于这个任务，RF 已经足够好」**。

- BiLSTM 可能有 +0.02-0.03 F1 提升，但**不可部署**（非因果、>1MB、需 GPU）
- TCN 虽然因果，但 Rep F1 (0.69) **低于** RF (0.78)，且训练不稳定
- 在「精度-延迟-可部署性」三角中，RF 取得了**最佳平衡**

**论文叙事**：
> "我们系统性地评估了从简单启发式（Peak Detection）到深度模型（TCN, BiLSTM）的完整方法谱系。实验表明，对于结构化良好的时序检测任务（阻力训练 rep 切割），精心设计的因果 Random Forest 在 7-fold LOSO 上达到 F1=0.778 ± 0.057，不仅超越了所有可部署的基线方法，还超过了非因果的 Sliding-window RF（F1=0.768）。这证明在适当的特征工程和上下文窗口设计下，经典 ML 方法可以达到甚至超越深度学习的性能，同时满足严格的实时部署约束。"

### 2.3 为什么没有选 XGBoost/CatBoost？

**3-Fold Head-to-Head 对比**（haoyu, hsianshun, kevin，相同特征、无 smoothing）：

| 方法 | Rep F1 | 训练时间 | 部署复杂度 |
|------|--------|----------|----------|
| CatBoost | 0.674 ± 0.041 | 4.0s | **高**（需 runtime） |
| Random Forest | 0.654 ± 0.062 | 9.3s | **低**（可手写 C） |
| XGBoost | 0.647 ± 0.037 | 2.3s | **高**（需 runtime） |

**结论**：
- CatBoost raw 分类稍好 (+0.020)，但加上 smoothing 后差距可能只剩 +0.01
- 部署复杂度远高于 RF（需 boosting runtime，ARM 移植困难）
- 论文叙事：「经典 ML 方法在精心设计的特征工程下达到深度学习级别的性能」比「我们用了一个复杂的梯度提升模型」更有说服力
- **最终决定**：保持 RF 作为主推方法

## 三、部署路径分析

### 3.1 LuckFox Pico Zero 可行性

| 组件 | 规格 | RF 需求 | 可行性 |
|------|------|---------|--------|
| CPU | ARM Cortex-A7 @ 1.2 GHz | ~1000 次 if-else/样本 | ✅ 轻松 |
| RAM | 64 MB DDR2 | ~1.6 MB（8 models） | ✅ 只占 2.5% |
| Flash | 视配置 | ~1.6 MB | ✅ 极小 |
| NPU | 0.5 TOPS | 不需要 | ✅ 纯 CPU |

### 3.2 板子部署路径

**路径 A：纯信号处理（Peak Detection）**
- 代码量：< 50 行 C
- 内存：~1 KB
- **精度低，通用性差**

**路径 B：Per-Action 树模型（Causal RF）** ← **主推**
- 代码量：~500 行 C（决策树遍历 + 特征提取）
- 内存：~1.6 MB（8 models）
- **精度高，可部署**

**路径 C：NPU 加速（备选）**
- PyTorch → ONNX → RKNN (INT8) → NPU
- 需验证 RKNN 对决策树的支持
- 若不支持，考虑 tiny MLP
